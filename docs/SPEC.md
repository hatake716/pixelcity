# PIXELCITY 仕様書 v0.1

ゲームボーイ風ビジュアルの都市経営シミュレーション。プレイヤーは市長として、
**財政を破綻させずに人口を最大化する**ことを目指す。

この文書が仕様の正典。実装で迷ったらここを参照し、変更したらここを更新する。

## 1. コンセプト

| 項目 | 内容 |
|---|---|
| 目的 | 人口の最大化。財政破綻（資金がマイナスで12か月継続）でゲームオーバー |
| 操作 | タッチ。1本指でタップ配置・ドラッグでパン、2本指でピンチズーム |
| 進行 | リアルタイム進行の「月」。1か月 = 既定8秒。一時停止/1x/2x/4x |
| 画面 | 縦持ち。上部にステータスバー、中央にマップ、下部にツールバー |

## 2. ビジュアル

### 2.1 パレット（v0.3 でフルカラーへ変更）

**16ビット機ふうのフルカラー**。色は用途ごとに名前をつけて `ui/Palette.kt` に並べ、
スプライトはその索引を持つ。当時の実機と同じパレット方式で、
 - スプライトは「屋根の色」とだけ書けばよく、配色を後から変えても絵が壊れない
 - 1画素1バイトで済み、大きな絵でも軽い
という利点がある。すべての色は **5bit/ch**（各色32段）に丸めて、当時の色の刻みに合わせる。

配色は「自然な都市の色」。緑の草地、青い水、灰色の舗装、赤瓦とベージュの住宅、
青いガラスの商業ビル、赤茶の工業、黄色い窓の明かり。
モニュメントは素材ごとに、鉄骨の赤・砂岩・白大理石・銅の緑青を使い分ける。

`android.graphics.Color` は単体テストでは中身のない stub なので、
Palette では使わずビット演算で色を組み立てている。使うとテストで全色が黒になる。

以下は v0.2 までの記述（緑の単色だったころ）。

### 2.1 旧パレット（DMG 4階調）
オリジナルのゲームボーイ（DMG）の緑4階調を採用する。色はコード内の定数のみで、
任天堂の素材・ロゴ・書体は一切使用しない。

| 名前 | 用途 | RGB |
|---|---|---|
| `GB_LIGHTEST` | 背景・空き地 | `#9BBC0F` |
| `GB_LIGHT` | 地面・薄い面 | `#8BAC0F` |
| `GB_DARK` | 建物の面・文字 | `#306230` |
| `GB_DARKEST` | 輪郭・影・強調 | `#0F380F` |

中間色は**使わない**。アンチエイリアスを切り、ディザ（市松模様）で階調を作る。

### 2.2 描画方針（v0.2 でクォータービューへ変更）

**視点は斜め見下ろし（クォータービュー）**。**64×32** の菱形タイルを敷き詰め、
x が右下、y が左下へ伸びる。建物は屋根の菱形と左右の側面でできた箱として描き、
左上からの光を想定して屋根・左面・右面を塗り分けることで立体に見せる。
手前の建物が奥を隠すよう、奥行き `tx+ty` の小さい順に描く。

**菱形と箱は式から生成する**。手で1行ずつ書くと幅がずれて壊れるため、
`IsoTiles` / `IsoBuildings` / `MonumentSprites` はすべて生成している。
敷き詰めたときに隙間や重なりが出ないことを `IsoTilesTest` が検査する。

**タイルは 64×32**（従来 32×16 の縦横2倍＝面積4倍）。窓枠・瓦の筋・日よけの縞・
赤十字・煙突といった細部を描き込めるだけの面積を確保している。

**縮尺は4段**（ぜんたい 1/8・ひろい 1/4・ふつう 1/2・よせる 1/1）で切り替えられる。
タイルが2倍になったぶん、分母も2倍にして見える範囲を保っている。
128×128 のマップ全体を1画面で見渡せるよう、引いた画を厚くしてある。

**タイトルの背景**は、本編と同じ `City` と `CityRenderer` で組み立てた
60×60 の完成形の街（`ShowcaseCity`）。このゲームで行き着く先を見せる。

以下は v0.1 時点の記述（真上からの視点だったころ）。
- 論理解像度は **320×288**（DMG 160×144 の2倍）。横幅に合わせた整数倍で拡大し、
  `FILTER_BITMAP_FLAG` を切って**ドットをドットのまま**引き伸ばす。
  縦は端末の縦横比に合わせて 288〜640 の範囲で伸ばす（細長い端末でマップを潰さないため）。
  - **2倍にした理由**: 同梱フォント DotGothic16 は 16px 四方の格子で設計されていて、
    8px で描くと1ドットが半ピクセルに落ちて日本語が崩れる。実解像度にこだわるより、
    文字を 16px で描いて読めるようにするほうを採った。タイルは 8×8 のドット絵を
    2倍に拡大して使うので、見た目の粒はDMGのままになる。
- マップは**クォータービュー（アイソメトリック）ではなく真上からの正方タイル**。
  実装が単純で、当時の携帯機のタイトルの見た目にも合う。
  タイルの絵は 8×8 で持ち、画面には 16 論理ピクセルで描く。
- モニュメントは 2×2 タイル（16×16 の絵を 32 論理ピクセルで描く）。
  地形と同じ周回で描くと右下が欠けるので、**描画は周回を分ける**。
- スプライトはコード内の**ビットマップ配列**（1タイル = 8×8 の 0..3 の値）で保持する。
  外部画像素材を持たないため、ライセンス上の懸念がない。

## 3. マップ

- 既定サイズ **128×128 タイル**（16,384 タイル）。海・川・地面の地形を起動時に生成（シード固定可）。
  - 地形の特徴はマップの広さに比例させる。海の厚みは `height/10`、
    川は `width/48` 本・幅 `width/64`。32×32 のころと同じ見た目も保たれる。
  - 中心の平地（`clearStartingArea`）も `width/5` × `height/7` に広げる。
  - 施設の影響範囲は半径で頭打ちなので、1タイルあたりの計算量は広げても増えない。
    128×128 を埋め尽くしても1か月あたり数ミリ秒で終わる。
  - セーブは1タイル3文字なので約48KB。SharedPreferences で扱える大きさ。
- 座標 `(x, y)`、各タイルは 1 つの `Tile` を持つ。
- 地形: `LAND`（建設可）, `WATER`（建設不可・隣接は地価+）, `SHORE`

## 4. 区分（ゾーニング）と建物

### 4.1 ゾーン
プレイヤーは土地に「区分」を指定する。区分は自動で発展し、段階（0〜3）を持つ。

| 区分 | 記号 | 設置費 | 役割 |
|---|---|---|---|
| 住宅 | R | 40 | 人口が住む。職と電力と道路が必要 |
| 商業 | C | 60 | 職を供給。税収の主力 |
| 工業 | I | 60 | 職を供給。公害を出す。地価を下げる |

### 4.2 インフラ・施設
| 施設 | 費用 | 月維持費 | 効果 |
|---|---|---|---|
| 道路 | 8 | 1 | 隣接がないと区分は発展しない。交通を運ぶ |
| 発電所（火力） | 900 | 40 | 電力 +2000。公害大 |
| 発電所（太陽光） | 1600 | 25 | 電力 +1600。公害なし。人口3000から解禁 |
| 公園 | 60 | 2 | 半径4の地価+・公害- |
| 警察署 | 300 | 20 | 半径8の治安+ |
| 消防署 | 300 | 20 | 半径8の防災+ |
| 学校 | 400 | 30 | 半径10の教育+。人口上限に寄与 |
| 病院 | 500 | 35 | 半径10の健康+ |
| 農地 | 30 | 2 | 半径3の公害-・地価+。職は生まない |
| 風力発電 | 700 | 18 | 電力 +900。公害なし。人口1,000から解禁 |
| 鉄道 | 40 | 3 | 道路と同じく交通網になる。半径4の地価+。人口2,000から解禁 |

### 4.3 発展の条件
各区分タイルは毎月、以下を満たすと段階が上がる（満たさないと下がる）。
1. 道路に隣接（4近傍のいずれかが道路、またはそこから道路網で繋がっている）
2. 電力が供給されている（電力総量 ≥ 需要）
3. 需要（`demandR/C/I`）が正
4. 地価・治安・公害の局所条件

## 5. シミュレーション（毎月）

順序は固定。テストで検証する。
1. 電力の充足を計算（供給 ≥ 需要か）
2. 各タイルの局所値を更新（地価・公害・治安・教育・健康）
3. 需要 `demandR/C/I` を再計算
4. 各区分タイルの段階を更新
5. 人口・雇用を集計
6. 税収 − 維持費 を資金に加算
7. 目標・チュートリアルの達成判定

### 5.1 人口
```
tilePop = stage * 段階係数(区分)   # 住宅: 段階1..3 → 8, 20, 40 人
population = Σ tilePop
```
人口の伸びは、雇用・電力・地価・教育・健康の充足度で頭打ちになる。

### 5.2 財政
```
月収 = Σ(区分タイルの評価額) * 税率
月支出 = Σ(施設の維持費) + 道路維持費
資金 += 月収 − 月支出
```
税率は 0〜20% で調整可能。既定 7%。
- 税率が高い（>12%）と需要が下がり、住民が流出する
- 税率が低い（<5%）と需要は上がるが収入が細る

### 5.3 破綻
資金がマイナスの月が **12か月連続** でゲームオーバー。警告は6か月目から出す。

## 7. チュートリアル

**初心者が手取り足取り進められること**を最優先する。スキップ可能だが、
**完走すると都市経営の基盤（道路・発電所・住宅・商業・工業・公園）が揃い、
そのまま黒字で回り始める**ように設計する。

### 7.1 方式
- 画面下部に**吹き出し**で1ステップずつ指示を出す。
- 対象のツールボタン・マップ位置を**点滅する枠**で示す（どこを押すかが必ず分かる）。
- そのステップで**必要な操作以外は受け付けない**（誤操作で詰まらない）。
- 各ステップは「なぜそれをするのか」を1〜2文で説明する。
- チュートリアル中は資金を減らさない（`tutorialGrant` で補填）。

### 7.2 ステップ
| # | 内容 | 達成条件 |
|---|---|---|
| 1 | ようこそ。市長就任の挨拶と目的（人口を増やす）の説明 | 「つぎへ」 |
| 2 | 画面の見方（資金・人口・月・需要メーター）の説明 | 「つぎへ」 |
| 3 | 道路を敷く。「建物は道路がないと発展しない」 | 道路を10タイル設置 |
| 4 | 発電所を建てる。「電気がないと街は育たない」 | 火力発電所を1つ設置 |
| 5 | 発電所から道路を繋ぐ | 発電所が道路に隣接 |
| 6 | 住宅区分を指定する。「区分は自動で発展する」 | 住宅を6タイル設置 |
| 7 | 商業区分を指定する。「職がないと人は住み着かない」 | 商業を3タイル設置 |
| 8 | 工業区分を指定する。「工業も職を生むが公害を出す」 | 工業を3タイル設置 |
| 9 | 時間を進める。速度ボタンの説明 | 3か月経過 |
| 10 | 人口が増えたことを確認。公園で地価を上げる | 公園を2つ設置 |
| 11 | 税率の説明。上げすぎると人が逃げる | 税率画面を開く |
| 12 | 卒業。モニュメントの存在と目標を伝える | 「はじめる」 |

完走時点で概ね: 資金 2,000 / 人口 150〜300 / 黒字 の状態になるよう係数を調整する。

### 7.4 詰まないための決まりごと

実際に遊んで、初心者が手詰まりになる経路が複数見つかった。以下を守ること。

- **設置数は、そのチュートリアル自身が敷かせた道路の周りに収まること。**
  一直線の道路 N マスに接するのは `N*2+2` マス。道路10・区分12・発電所1・公園2 で
  15 ≤ 22 に収まっている。`TutorialTest` がこの関係を検査している。
- 道路に接していない区分・発電所は設置させない。置けてしまうと
  「建てたのに育たない街」ができ、原因が分からないまま詰まる。
- 置ける場所は点滅する枠で示す。「道路のとなり」と言われても、
  初心者にはどこが該当するのか分からない。
- そのステップの道具を自動で選ぶ。道具を探させると、
  見つけられないまま他の操作も塞がれて詰む。
- 求められた数を超えて置かせない。資金と土地の無駄になる。
- 施設の上に区分や道路を重ねさせない。発電所を消して街を停電させる事故が起きた。
- 地形生成の中心は必ず平地にする（`clearStartingArea`）。
  中心が川や海だと、最初の道路すら引けない。

### 7.3 スキップ
タイトルで「チュートリアルをとばす」を選ぶと、初期資金 20,000 のみで白紙から開始。
チュートリアル完走時は初期資金 20,000 + 整備済みの街。

## 7.5 お手本の街

タイトルの「おてほんから はじめる」で、完成した街を選んでその続きから遊べる。
3種類とも、そのまま黒字で回る状態にしてある（`ShowcaseCityTest` が検査）。

| 見本 | 性格 | 人口の目安 |
|---|---|---|
| だいとし | 人口と密度が最大級。財政とのつりあいが取れている | 約16,000 |
| でんえんとし | 農地と緑が豊か。火力を使わず太陽光・風力・鉄道でまかなう。公害が最少 | 約8,500 |
| こうぎょうとし | 工業が中心。資金がいちばん厚い | 約7,000 |

テストで守っている性格:
- どれも黒字で、電力が足りていて、12か月まわしても人口が崩れない
- 大都市がいちばん人口が多い
- 田園都市は火力発電が0で、公害がいちばん少ない
- 工業都市は工業が住宅より多く、資金がいちばん厚い

## 8. セーブ

- `SharedPreferences` に JSON で保存。オートセーブは毎月と `onPause`。
- **スロットは10個**（`SaveGame.SLOT_COUNT`）。遊んでいるスロットへ自動で保存し続ける。
  - タイトルの「つづきから」でスロット一覧を出し、選んで再開する。
  - 「はじめから」は、空きがあればそこへ、なければ上書きするスロットを選ばせる。
  - 一覧の長押しで消す（確認ダイアログ付き）。
  - 一覧には要約（人口・年月・資金・チュートリアル中か）だけを出す。
    街の中身は選ばれてから読むので、10個あっても待たされない。
- 保存内容: マップ全タイル・資金・人口・月・税率・建設済みモニュメント・チュートリアル進捗。
- **旧版（1スロットだけ）の保存は、初回起動時にスロット1へ引き継ぐ**（`migrateLegacySave`）。
  これがないと、更新した人の街が消える。`SaveSlotTest` が検査している。

## 9. 音

外部音源は使用しない。`tools/` のスクリプトで矩形波・ノイズから生成した
PCM WAV を同梱する（オリジナル、MIT）。v0.1 では効果音のみ（設置・却下・達成）。
