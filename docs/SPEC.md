# PIXELCITY 現行仕様

この文書は実装の現在形を説明する。過去の160×144・4階調・11手順という記述は現行版に適用しない。

## 1. 実行構成

- Android API 26以降。compile/target SDK 36、Java 17、Kotlin 2.2.20、AGP 8.13.0。
- MainActivity（ComponentActivity）がタイトル・保存枠・お手本選択・GameViewを切り替える。
- CityはAndroid非依存の都市状態と月次計算。UIはカスタムView。
- CityのCampaignが就任後の三つの都市シナリオ、政策費、住民信頼、企業協定、防災、完成記録を管理する。
- 画像はByteArrayのパレット索引 → PixelCanvas → ARGB Bitmap → Android Canvas。
- 秘書ひよりの肖像は同梱PNGを読み込み、会話欄の枠内へ端末解像度で重ね描きする。
- 論理画面は端末寸法から算出する。基準横幅480、最大横幅900。整数倍で画面へ描画。
- 1タイルの元画像は512×256。通常の表示倍率は1/8、操作範囲1/64〜1/2。
- AudioTrackで独自のPCM効果音15種と5曲のBGMを鳴らす。都市シナリオ・人口・財政で選曲し、設定でそれぞれ停止できる。[音の設計](AUDIO_DESIGN.md)。

## 2. 都市と操作

新規都市は512×512マスを球面に表示し、NASAの衛星画像とGEBCO由来の地形資料による自然な地球から、初期都市の平野（X=121・Y=102）を選ぶ。中央の矩形平野は生成しない。初期資金20,000、税率7%、1900年1月開始。都市画面はクオータービューを維持する。全マスを無料の地形編集で11種類の地形へ変更でき、初期範囲の外も平野にすれば同じ都市を建設できる。詳細は[惑星仕様](PLANET.md)。
地形は陸・水・岸。新規都市の中心は建設可能に整地する。海上建設・橋は未実装。

地図は1本指で複数マスを選択し、費用を確認して実行する。選択の取消しで建設は起きない。
費用は新設費と必要な撤去費を含む。同じものが既にあるマスや空地の撤去は選ばない。
2本指での移動・ピンチ開始やタッチ取消し時は、そのジェスチャー直前の選択を復元する。

道路・大通り・高速・鉄道・地下鉄、R/C/I区画、電力・水・ゴミ・公共施設、公園・農地などを置ける。
施設の上に別のものを置くには明示的に撤去する。区画・交通施設の置換には撤去費を加算する。
モニュメントは2×2を占め、どの占有マスを撤去しても全体が消える。

「しらべる」は建設と独立した調査モード。敷地の接続、電気、水、地価、公害、安全、教育、健康、犯罪、
交通量、埋立残容量、維持費または成長の条件を表示する。

## 3. 月次計算

通常8秒で1か月。速度は0・1・2・4・10・30倍。1フレーム最大4か月。
メニュー表示中と就任日誌の会話・配置手順では月を進めない。
成長を見守る手順は住民や住宅の実状態で達成し、最終手順はサービスを保った3か月連続黒字で達成する。
パネルを閉じた後に、読んでいた時間の分をまとめて進めない。

月の更新順：

1. 月を加算する。
2. 道路接続、電力、水、交通、地価・サービス、犯罪を計算。
3. ゴミ処理と感染度を進める。
4. R/C/I需要を更新し、各区画の段階を更新。
5. 人口・雇用と税収・維持費を集計し、資金へ反映。
6. 災害を判定。田園シナリオでは独自の天候リスク・防災・応急費を計算。
7. 最新の敷地状態から派生値を再計算。シナリオの信頼・事件対応費・章達成・都市完成を判定し、履歴・破綻を更新。

`recomputeDerivedState()` は道路・電力・水・交通・局所値・犯罪・人口・ゴミの需給を復元する。
月、資金、感染度、ゴミ滞留、埋立量、需要の平滑化、履歴は進めない。
`refreshBudgetForecast()` は資金を動かさず収支見込みを集計する。

## 4. 交通と電気

発電所に接する交通網から幅優先探索する。道路・大通り・高速・鉄道・地下鉄が網を形成する。
区画が直接アクセスできるのは道路・大通り・鉄道。高速や地下鉄の隣だけでは沿道アクセスにならない。
この交通網はゲーム用の共通接続モデルであり、車と鉄道の乗換えを個別には計算しない。

電気は発電所から、交通網・送電線・隣接建物を通る。系統ごとに発電量を集計し、
索引順に供給可能な建物へ配る。離れた未接続の発電所の余剰は利用できない。
節電条例ではタイルごとの需要を15%削減し、整数で切り上げた同じ需要を表示と割当に使う。

| 発電施設 | 供給 |
|---|---:|
| 火力 | 2,000 |
| 太陽光 | 1,600 |
| 風力 | 900 |

区画の需要は8 + 段階×12、その他の建物は10、発電所自身と交通・送電線は0。
建物へ電気が届くことと、交通アクセスがあることは独立した条件。

交通量は住宅段階から発生し、近隣の商業・工業への距離による重みで周囲の交通網に伝播する。
道路の容量は600、大通り1,900、高速4,000、鉄道3,000、地下鉄6,000。
遅延は `1 + 0.15 × (交通量/容量)^4`。渋滞・地図の重ね表示・走行速度はこの容量比を基準にする。
A〜Fはゲーム内の便宜的な混雑段階で、0.8を超えると渋滞扱い。
現実の交通予測の精度や、完全なOD配分・利用者均衡を保証するものではない。
バス停・地下鉄駅・条例は周辺の交通量を軽減する。

## 5. 水・環境・サービス

給水塔は供給1,200・範囲10、浄水場は4,000・範囲14（マンハッタン距離）。水道管は不要。
水は施設の範囲内へ順に割当てる。発電・給水の全体比率だけでは局所的な未接続は分からないため、調査・重ね地図で確認する。

住宅・商業・工業は段階ごとに3・2・5のゴミを出す。条例で排出量を25%削減できる。
処理は焼却・再資源化を優先し、残りを埋め立てる。滞留分も処理対象。
埋立は1施設12,000まで。残容量を超えず、満杯は新規受入を停止。撤去後の新設は埋立量0で始まる。

地価・公害・安全・教育・健康は施設と距離で計算。犯罪は密度・失業・地価・教育・安全から算出する。
感染度は毎月徐々に変化し、水不足・ゴミ・公害・人口密度・医療が影響する。

条例はパトロール、教育、無料診療、省エネ、リサイクル、公共交通の6つ。人口に比例した費用が発生する。
通常の災害はなし・控えめ・普通・多いから選択でき、都市開始24か月は発生しない。
田園シナリオの天候リスクは別に管理し、ルート開始6か月後から設定にかかわらず発生し得る。

## 6. 成長と財政

R/C/Iは段階0〜3。住宅人口は0/8/20/40、商業雇用は0/10/24/48、工業雇用は0/12/28/56。
成長には交通アクセス・電気・需要・地域の質が必要。水がない場合は段階1まで成長する。
住宅は公害・犯罪・渋滞を嫌い、地価・教育・健康・安全を評価する。
位置ごとに-4〜+4のしきい値差を付け、需要は毎月最大12ずつ目標値へ動かす。
弱い需要不足ですぐ衰退させず、強い不足や品質不足で段階を落とす。

税額は段階・地価・用途の評価額から計算する。税率は0〜20%。
合計税額の端数は、税目の小数部分が大きい順に配り、内訳と合計を一致させる。
維持費・条例費を差し引いた差額を毎月資金へ反映。負債が12か月継続すると破綻する。
グラフ用の履歴は直近120か月。再開時も前の収支・需要を保持する。

## 7. 建築・お手本・手引き

`Architecture.kt` が世界座標から窓、石積み、切妻・マンサード屋根、屋根窓、煙突、
日よけ、屋上庭園、噴水、樹木、店先を描く。R/C/Iの54種類と公共・インフラ20種類。
`IsoBuildings.kt` はキャッシュと9様式の配色、`MonumentSprites.kt` は8ランドマークを担当。
`SpriteScale.kt` は面積平均による縮小と上限付きキャッシュを担当する。
`CityRenderer` は地面と透過建物レイヤーを再利用し、車・選択・重ね地図は別に更新する。
地図、カメラ、配色、成長アニメーションの変化でレイヤーを描き直す。
建物の形は位置から固定で決まる。描画は成長段階とともに変わる。
歩行者やヨットは景観描写で、個人単位の経路探索や船の物流計算はない。

新規都市はチュートリアルあり・なしを選べる。就任日誌は秘書ひよりとの5章18場面の物語。
開始時の資金20,000で小さな通りから経営し、自動補助金は入れない。広場/診療所の選択は施設・費用・結末へ反映。
本文ではなく、返答ボタンで会話を進める。配置候補と実行/取消を併用し、調査・予算・情報は随時使える。
[詳しい構成・旧版からの移行](TUTORIAL_STORY.md)。
お手本は「こもれびの みなとまち」「だいとし」「でんえんとし」「こうぎょうとし」。
いずれも同じCityとして経営を継続する。強制的に全建物を通電状態にはしない。

## 8. 保存

SharedPreferences `pixelcity` の `city_0`〜`city_9` にJSON。形式v5。v1〜v4も読込可能。
タイルは固定saveIdを文字へ符号化し、列挙の並べ替えに影響されない。
都市・条例・外観・手引き・感染・ゴミ・埋立量・履歴・需要・収支を保持する。
就任日誌は内部版2。固定場面ID・公共投資の選択・会話確認・連続黒字と最終集計月を保存する。
旧26手順の途中保存は街を保持し、日誌のみ冒頭へ移行する。終了済み・スキップ済みは再開しない。

未来の形式、不正な寸法、途切れたタイル配列などは読み込みを断る。元データは自動削除しない。
壊れたJSONの枠はエラーとして表示し、新規都市用の空き枠として扱わない。

シナリオのルート・章・政策・信頼・完成記録・最近の事件も保存する。
就任後の3ルートと月次効果・完成条件は [SCENARIOS.md](SCENARIOS.md) を参照。
旧単一枠のデータは最初の空き枠へ移し、全枠が埋まっている場合は旧データを保持する。

AndroidのOSバックアップ・端末移行に保存設定が含まれる。アプリ自身のネットワーク権限・通信機能はない。

## 9. 検証

`testDebugUnitTest`：経営・成長・接続・交通・保存互換・再開の再現性・建築・座標・描画。
`connectedDebugAndroidTest`：エミュレータの保存枠・選択・ピンチ・設定・実Activityの税率/調査/再開始。
`lintDebug`：Android静的解析。単なるビルド成功と画面・操作確認は区別する。
