# バランスと検証

数値を変更したら、成長・財政・公共投資・電力不足・チュートリアル後の継続を、
実際に月を進めるテストで確認する。単月の見た目や人口だけで経営可能と判断しない。

## 成長モデル

- 基礎地価26、岸34。段階0/1/2の成長に必要な品質は8/20/34に位置ごとの差を加える。
- R/C/I需要は1か月最大12ずつ変える。弱い需要不足で即座に全区画を撤去しない。
- 電力不足は系統ごとに部分停電。道路接続と給水範囲は建物単位で評価する。
- 水道は上位段階への成長条件。サービス・公害・犯罪・混雑が品質を変える。
- 集計上の人口最大化と、資金・住み心地・環境の維持にはトレードオフがある。

## 検証用都市を正しく作る

従来の公共投資テストでは学校・病院・警察の予定位置が道路と重なり、配置されていなかった。
配置位置を修正し、比較都市には上位段階を賄うだけの発電所を用意した。
サービスの有無と電力不足を混同して比較しない。

従来の大通りテストは人口0で解禁済みでない道を建設していた。
現在は解禁条件を満たし、建設成功・住民の存在・実際の交通量・容量比の低下を確認する。

## テストの対象

- `BalanceTest`：長期間の成長と収支、人口の安定、公共投資の効果、部分停電、税率。
- `SystemsTest` / `TrafficTest`：水・環境・交通・条例と容量比。
- `TutorialTest`：5章18場面、広場/診療所の両方を通常建設と月次計算で完走。
  補助金や解禁の迂回なしで、道路12・住宅8・商業4・工業2などの標準案を検証する。
  標準案の税率例は広場8%、診療所9%。実際の収支で調整する。完走後24か月の自立運営も確認。
- `ShowcaseCityTest`：お手本4都市を24か月運営し、電力・人口・資金の継続を確認。
- `RenewalRegressionTest`：大通り/高速の接続、実際に効く節電、系統分離、送電線、
  v3互換とv4の保存再開、12か月の再開再現性、ゴミ処理と埋立リセット、調査の助言。
- 端末テスト：30件の既存操作/保存確認に加え、実Activity上の税率操作・調査・削除後のライフサイクル。
  `StoryFlowTest` は「はじめから」から完走までの画面操作、日誌の復元、読書中の時計停止を検証する。

検証画像は `-Ppixelcity.preview=<絶対パス>` で出力する。建物は実際の生成結果を比較する。

ここに固定した人口の参考値は置かない。仕様と設備構成が変わると参考値も変わるため、
必要な数値は対象コミットのテストやシミュレーションで測定する。
