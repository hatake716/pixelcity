# バランス調整の記録

数値を触るときは `BalanceTest` を必ず通すこと。このテストは
「人口が育つ」「振動しない」「公共投資が報われる」を守っている。

## 直した振動の問題（v0.1 開発時）

最初の実装は、全区分タイルが同じ条件で同時に成長・衰退したため、
街全体が2〜3か月の周期で明滅し、人口が 968 ⇄ 2516 を往復して
まったく安定しなかった。原因は3つで、順に潰した。

### 1. 公害と地価で成長の最初の一段が登れない
基礎地価 12 に対して段階1の要求が 22 で、公園を置かない限り
どの住宅も stage 1 で止まっていた。さらに公害が `landValue - pollution/3` で
地価を潰し、発電所の近くは地価 0 になっていた。

- 基礎地価 12 → 26（水辺 22 → 34）
- 公害の地価への影響 `/3` → `/5`
- 発電所の公害 40・半径7 → 26・半径5、工業の公害 10・半径4 → 7・半径3
- 住宅の公害への感度を半分に
- 段階の要求値 6/22/42 → 8/20/34

### 2. 需要が目標値へ一気に飛んで振動した
`demandC` などが毎月いきなり目標値になるため、区分が一斉に成長すると
雇用が跳ね、翌月に需要が -100 まで落ちて一斉に崩れた。

→ `approach()` で1か月に動ける幅を `DEMAND_STEP = 12` に制限した（平滑化）。

### 3. 電力が全か無かで、街が丸ごと明滅した
`supply >= demand` が偽になった瞬間、**全タイル**が停電していた。
需要が供給線をまたぐたびに街全体が消え、これが振動の主因だった。

→ 供給できる分を索引順に配り、足りなかったタイルだけ停電させる**部分停電**に変更。

### 4. 区分の足並みが揃いすぎた
上記を直しても、同一条件のタイルが同時に閾値をまたぐため小さな波が残った。

→ タイル座標から決まる `jitter`（-4..+4）を要求値と必要需要に加え、
   成長のタイミングをずらした。位置から決まるので再現性は保たれる。
→ 弱い需要不足で即衰退せず、`demand < -30 + jitter` のときだけ衰退させる
   ヒステリシスを入れた。

## 現在の目安（32×32 を敷き詰めた場合）

| 街 | 150か月後の人口 | 備考 |
|---|---|---|
| 区分と道路と電力のみ | 約 3,250 | stage 3 はほぼ出ない |
| 公園・学校・病院・警察あり | 約 3,700 | stage 3 が 30 タイル前後 |

公共サービスへの投資が 1.1 倍以上の人口になることをテストで保証している。
