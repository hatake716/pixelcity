# 就任日誌 ― 秘書ひよりと始める市政

0.2.1の「はじめから」で始まる5章18場面の物語。
新米市長が、秘書ひよりと最初の住民を迎え、住民への約束を果たし、財政を自立させる。

## 構成

| 章 | 場面 | 実際の目標 |
|---|---|---|
| 着任の日 | 空っぽの市長室 → 最初の道 → 帰り道の灯り → 住宅 → 引っ越しの朝 | つながる道路12マス、火力1、通電した住宅8、住民32人 |
| はじめての住民 | 転入届 → 屋根の向こうの暮らし → 蛇口から始まる未来 | 入居済みの住宅を調査し、給水塔1を置く |
| 小さな商店街 | パン屋の出店 → 街を支える工房 → 商店街の成長 | 商業4、工業2、住民120人・雇用40人分・段階2以上の住宅4軒 |
| 市長の約束 | 二つの希望 → 約束の実現 → にぎわいの舞台裏 | 公園2または診療所1を選んで建設し、埋立地2を用意 |
| 最初の決算 | 市政ノート → 予算会議 → 三か月の約束 → 最後の手紙 | 情報と予算を確認。住民120人以上・サービス維持・3か月連続黒字 |

最後の手紙には、選んだ公共投資、実際の人口、直近の黒字額が反映される。
最後の返答で物語を閉じると、0.3.0以降は同じ街を引き継ぐ[三つの都市シナリオ](SCENARIOS.md)を提案する。
すぐに選ばず街へ戻ることもできる。

## 遊びとしての変更

- 道路230マス、住宅70マスなどの大量配置を、一本の小さな通りから始まる内容に変更。
- 24/24/48/60か月を待つ条件を廃止し、実際の入居・建物の成長・連続黒字で進める。
- 初期資金20,000を使う。旧版の資金が減るたびに20,000を補填する処理は廃止。
- 緑の広場は建設120・維持費月4。診療所は建設250・維持費月18。選択は実際の施設と暮らしに残る。
- 予算は現在の設備と税率による見込みを表示。税率変更後に再計算し、資金や月は動かさない。
- 標準配置例では広場8%、診療所9%の税率で検証。実際の都市に対する固定の正解ではなく、収支を見て調整する。
- 新しい施設をすべて置かせる内容にはしない。公共交通や高度な施設は、人口と課題に応じて自由経営で導入する。

## 秘書と操作

0.2.2から、栗色の髪・翡翠色の瞳・深緑のジャケットのひよりを描いた専用イラストを使用する。
紙色の会話欄には112×112論理ピクセルの肖像枠を設け、顔と表情が分かる大きさにした。
画像は端末解像度で描画する。キャラクターの[デザインと来歴](HIYORI_DESIGN.md)も参照。
本文を押しても話は進まない。明示的な返答ボタンで話を受け、作業中は目標・現状への助言を表示する。
「ひよりに相談」で会話を読み直せる。「候補地へ」で見失った場所へ戻れる。

配置候補は任意。無料の建物を生成せず、通常の建設費・維持費・接続判定・成長計算を使う。
道路の孤立した置き方は避け、施設は道沿いへ誘導する。修正のための道路・送電線・撤去も認める。
道路は最大の連結部分を数え、住宅・施設は道路接続と通電を確認して目標に数える。

調査・予算・情報は他の場面でも参照できる。成長・決算の場面では建設や税率を自由に調整できる。
会話や配置中は時計を止める。メニューを読んだ時間を、閉じた後にまとめて進めない。

## 最後の判定

3か月それぞれについて、次を満たす必要がある。

- 人口120人以上、資金0以上、破綻していない。
- 入居済み住宅に道路・電気・水道が届く。
- ゴミの処理能力が排出量以上である。
- 市長が選んだ公園または診療所が接続・通電して残っている。
- その月の実際の収入が維持費を上回る。

赤字やサービスの欠落で連続記録をリセットする。同じ月の通知を繰り返しても数えない。
ひよりは未接続、停電、給水範囲、ゴミ、税率、公害、赤字などを優先して助言する。

## 保存互換

0.3.0の都市JSONはv5。日誌の配列は内部版2のまま保持する。
場面の固定ID、会話を読んだ状態、公共投資の選択、連続黒字、最後に数えた月も保存する。

旧26手順の途中保存は、都市・資金・年月を保持し、日誌のみ新しい冒頭へ移す。
ひよりが引継ぎを説明し、既存の設備が条件を満たしていれば確認後にその場面を通過する。
旧版で終了済み、またはチュートリアルをスキップした街を、勝手に物語へ戻さない。

## 検証

`TutorialTest` は両方の公共投資を32×32・128×128の都市で通常建設から完走する。
標準例はゲーム内6か月で修了し、以後24か月も補助金なしで継続できることを確認。
この経営比較は災害を無効にして行い、本編の新規都市の災害設定は変えない。
待つだけでは進まないケース、電気の復旧、孤立道路、撤去、空地の誤調査、赤字による連続記録リセット、
選択と会話・進捗の保存、旧版の日誌移行も検証する。

`StoryFlowTest` は実Activityの「はじめから」、会話・選択肢、地図の候補地、建設の実行、
住宅の調査、情報・税率の操作、時計による成長、最後の手紙までを画面の座標で操作する。
本文へのタップが建設・進行にならないこと、Activity再作成からの復元、メニュー読書中の時計停止も確認する。
