# 512×512の惑星と地形編集

0.6.2 / versionCode 17。都市そのものを球体で表示し、市政の息抜きとして開始時から無料で地形を編集できる機能。

## フィールド

- **一つのCityが512×512＝262,144マスを持つ**。従来の128×128から縦横4倍・面積16倍。
- 各1マスに独立した地形属性を保存する。16の都市区画に分ける構成ではない。
- 新規開始ではNASA / GEBCO由来の地形をそのまま使用。中央の128×128平野は生成しない。
- 通常の新規開始の初期地点は北米の自然な低地、X=121・Y=102。チュートリアルの道路と施設が置ける17×7の範囲を自然な平野の中から探索する。分類済みの地形を選ぶだけで、整地しない。
- 新しく開始する模範都市は、港町＝イギリス、大都市＝アメリカ東海岸、田園都市＝ヨーロッパ大陸、工業都市＝中国大陸。地域のつながった低地に道路・街区を配置し、建築するマスだけ平野に整える。海・川・山と未建設の地形を保持する。保存済みの模範都市は再配置しない。[地域配置の詳細](REGIONAL_CITY_VALIDATION.md)
- 地球の衛星画像の色、標高、緯度からゲーム用の平野・海・山・森林・砂漠・雪原などを分類する。地形編集で平野にした任意のマスに住宅・道路・施設を建設できる。
- 建設判定は都市モデルでも1マス単位。平野以外は建設不可。2×2の記念建築は敷地全てが平野でなければ建設できない。
- 資金・税率・公共サービス・交通・市政の物語は惑星全体で共通。場所を移動しても別都市にはならず、開始資金の再支給もない。
- 都市と惑星は同じ球面・同じ描画画面。街を斜めから見る近景と、星全体を見る遠景を連続して拡大縮小する。

## 操作

1. 「建設選択」で一本指による建設範囲の選択、「実行」で費用を支払って建設。「調査」で建物・敷地の情報を調べる。二本指で球体を移動、ピンチで拡大縮小する。
2. 「視点移動」では一本指で回転できる。「街の中心」で開始地点、「全景」で惑星全体へ移動。地形を変えるときは下部の「地形編集」、または市長メニューの「地形編集」を選択。同じ球面に編集トレイが開く。
3. 細かなマスを指定するには座標欄を押し、横X・縦Yに0〜511を入力する。
4. 「座標指定」で指定地点を拡大。「海面・海底」で海面を除いた海底を表示する。
5. 配置したい地形と筆の大きさを選び、「地形を適用 $0」で変更する。
6. 筆は**1マス、4×4、16×16、32×32**。筆の範囲も球面に表示する。経度の継ぎ目では東西に回り込み、南北端では範囲を切り詰める。
7. 「完了」で編集トレイを閉じ、その平野に都市の建設を続ける。別画面への移動は不要。
8. 「変更を戻す」で、現在のプレイ中の最大32操作を取り消せる。取消履歴自体は保存しない。
9. 地形編集の完了直後も一時停止。「時間」で市政の進行を再開する。
10. 地形編集中もBGMを再生する。市長メニューから開いた場合も曲を再開し、編集・取消で曲を最初から鳴らし直さない。BGM無効の設定を尊重し、アプリを背景に回すと音声を停止する。

## 3D地形

地球の基本形状は、標高・海底深度で頂点を変形した連続した球面メッシュ。表面は現在保存されている512×512マスの土地属性から生成する。各マスの色と水・砂・織り目などの表現は独自描画で、衛星写真を表面へ貼り付けない。

- 地形格子は経度と緯度の正弦で配置する等積の512×512。極と経度の継ぎ目を連続させる。
- 陸域の0〜6,400m、海底の−8,000〜0mの濃淡資料から高さを復元。見やすいよう**起伏を65倍**に誇張する。
- 通常は海面を基準半径に表示し、属性色と波・反射光を付ける。海底表示では負の高さを持つメッシュを表示し、深度に応じた明暗を付ける。
- 大気の縁に青い光を加え、方向光と地形法線で山脈の陰影を付ける。
- 地面の形状は全景で2マス刻み、拡大中の48×48範囲では1マス刻み。色・属性は常に512×512の全マスを参照し、2×2の隣接マスも個別に描く。等積格子の座標で1マスを選び、色の補間で隣の属性を混ぜない。隣接面で同じ境界頂点を使う。
- 地形編集で変更したマスは指定属性の色・高さへ置換し、取消でも表示を更新。拡大時には周辺32×32マス以内に`TerrainModels.kt`の独自3D形状を表示する。初期地形も編集済み地形も同じルールを使う。形状は描画した地表の三角形に沿って配置し、高さの二重加算による浮きや引き伸ばしを防ぐ。
- 近景では既存フェルトデザインの322種類の建築・車両・人物モデルを球面へ配置。道路・線路は1マスごとの接続方向を地表に描く。各敷地と建物の位置は同じ地表三角形に沿わせる。

| 属性 | 形状 |
|---|---|
| 平野 | 建設できる平らな地面 |
| 海 | 青い水面と小さな波の起伏 |
| 川 | 両岸を持つ蛇行した水路 |
| 山 | 独立峰と雪冠 |
| 山脈 | 高さの異なる複数の峰 |
| 火山 | 火山体、開いた火口、内部に沈んだ溶岩 |
| 森林 | 幹と樹冠を持つ複数の木 |
| 熱帯雨林 | 多層の樹冠が密集する木々 |
| 砂漠 | 丸い砂丘 |
| 雪原 | 雪で覆われた緩やかな丘 |
| 氷河 | 氷の稜線と谷 |

全景は地球の高低差と各マスの属性色、拡大表示は布の織り目・縫い目と立体物で表現する。都市画面もフェルトの質感を維持する。遠景で細かな立体物を省略している距離でも、表面の土地属性・編集・建設の単位は常に1マス。

属性表面は1 MiBのRGBAデータ。GPU資源の明示的解放、256 KiBの頂点転送バッファ、正確な頂点数による配列確保を維持する。密集した熱帯雨林でも詳細メッシュを64 MiB未満に抑える。
火山などは観賞用。地形の配置によって災害は発生させない。既存シナリオの都市災害設定とは別の機能。

## 編集と建築の保管

地形変更は市の資金を一切消費しない。地形編集トレイを開いている間は都市の時計を停止する。球体を表示する通常の建設画面では市政の時間が進む。

建築のあるマスを平野以外へ変える場合、建築の種類・発展段階・記念建築の情報・埋立量を保管し、地形を表示する。
平野に戻すと建築を復元する。2×2の記念建築は、筆が一部に触れた場合も敷地全体をまとめて変更し、部分的な破損を防ぐ。
保管中の記念建築は別の場所への重複建設も防ぐ。地形の変更・取消時に、実際に残っている建築から市政の状態を再計算する。

## 保存・既存都市

- 保存形式v7は512×512の都市、地形、保管建築、カメラ、筆、初期都市座標、地球データ版、海底表示、説明済みフラグを保存する。
- 既存の10保存枠を維持。1枠に1つの連続した惑星を保存する。
- v1〜v6はその都市を開いた際に自然な地球を生成し直す。旧都市の**建築のあるマスだけ**を初期地点基準で移動し、敷地を平野にする。空の四角い用地・旧海岸・旧形式で編集した地形は引き継がない。
- 資金・税率・物語は保持。保管中の建築は通常の敷地へ戻す。記念建築の索引と埋立地の索引を変換する。移動後に南北端を越える旧敷地は除外する。
- v7の地球は再生成せず、編集内容・建築をそのまま再開する。既存都市の地形互換性より自然な地球を優先するという今回の仕様による移行。
- 将来形式、欠けた地形配列、未知の地形、平野以外に直接置かれた建築などの矛盾した記録は読み込まず、元の保存を保持する。

## チュートリアル

就任日誌の終了後、ひよりが1回だけ短く御案内する。「市政を続ける」で既存の3シナリオへ、「地形を編集」で寄り道できる。
説明を読む前から機能自体は使用できる。説明済みの状態も保存する。

## 実装の所在

- `EarthTerrain.kt` / `Planet.kt`：実地球データ、512×512の初期地形、1マス単位の編集、筆、保管、取消。
- `Model.kt` / `City.kt`：地形属性と建築の保存状態、1マス単位の建設制限。
- `SaveGame.kt`：v7と旧都市の移動・地形再生成。
- `TerrainModels.kt`：11種の独自3D地形。
- `PlanetGeometry.kt`：球面の形状、詳細表示、三角形との交差によるタイル選択。
- `PlanetSurface.kt`：OpenGL ES 2.0、回転、連続ピンチ、斜めの詳細表示。
- `GlobeTown.kt` / `GlobeModels.kt`：不変の都市描画データ、フェルト建築・車両・人物の3D描画、建物選択、遠景モデルと24 MiBのGPUキャッシュ。
- `GlobeTerrainEditor.kt` / `MainActivity.kt` / `GameView.kt`：統合画面、地形編集トレイ、建設・調査・市政、保存、物語の案内。
- `FeltTerrainSprite.kt` / `RealisticCityRenderer.kt`：メニューの建築見本、タイトル背景、旧描画の回帰確認に引き続き使用。

惑星メッシュ・編集地形・シェーダーは独自実装。衛星画像・標高資料はNASA / GEBCOの公開資料から加工し、アプリ内に同梱。起動時の通信やAPIキーは不要。原資料URL・権利条件・ハッシュ・加工内容は`assets/earth/sources.json`、ライセンス画面と`licenses/Earth-assets.txt`に記載。再生成は`tools/planet/fetch_earth_sources.py`と`build_earth.py`（Pillow / NumPy / SciPy）を使用。

地形区分はゲーム用の推定。源資料は縮小された8bit濃淡図であり、厳密な測量モデルや現在の地表を保証するものではない。
