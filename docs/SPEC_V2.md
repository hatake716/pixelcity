# PIXELCITY v2 仕様 — 都市経営シミュレーターの全面拡張

既存の v0.4（区分・道路・電力・地価・公害・税収）に、
交通インフラ・環境整備・災害・犯罪・疫病・情報指標を加える。
**隣町との交易は扱わない**。あくまで独立した都市として完結させる。

ベンチマークした作品の考え方（実装は独自。素材・コードの流用はしない）:
- SimCity 2000/4: 区分の発展段階、需要バー、データマップ、条例、災害
- Cities: Skylines: 道路の階層、上下水道、ゴミ、渋滞の可視化、地区ごとの方針
- A列車で行こう / Transport Tycoon: 鉄道と旅客の流れ
- Tropico: 市民個人の状態ではなく、集計値で街の健康を測る考え方

## 1. 交通

### 1.1 道路の階層
| 種類 | 費用 | 維持 | 容量 | 備考 |
|---|---|---|---|---|
| 道路 | 8 | 1 | 100 | 既存 |
| 大通り | 24 | 3 | 300 | 幅が広く、渋滞に強い |
| 高速道路 | 60 | 6 | 800 | 区分は直接つながらない。出入口が要る |
| 鉄道 | 40 | 3 | 600 | 既存。公害を出さない |
| 地下鉄 | 90 | 8 | 900 | 地価を下げない。用地を取らない |

### 1.2 渋滞
各タイルに **交通量 `traffic`** と **容量 `capacity`** を持たせる。
- 発生: 住宅→職場（商業・工業）への移動量を、人口と雇用から求める
- 伝播: 交通網を流れる量を、幅優先で距離減衰させながら配る（経路探索は簡略化）
- 影響: `traffic > capacity` で渋滞。渋滞は地価を下げ、公害を増やし、区分の成長を鈍らせる

### 1.3 公共交通
| 施設 | 費用 | 維持 | 効果 |
|---|---|---|---|
| バス停 | 120 | 8 | 半径6の交通量 -25% |
| 地下鉄駅 | 400 | 25 | 半径8の交通量 -40%。地下鉄に接続が要る |
| 空港 | 3,000 | 120 | 商業需要 +20。公害・騒音あり。人口10,000から |
| 港 | 2,000 | 80 | 工業需要 +20。水辺に隣接 |

## 2. 環境整備（インフラ）

### 2.1 上下水道
- **給水塔**（300 / 20）: 半径10へ給水。人口に対して水量が要る
- **浄水場**（800 / 45）: 半径14へ給水。汚染された水を浄化
- **下水処理場**（900 / 50）: 半径12の水質汚染を除去
- 水が足りないと区分は育たない（電力と同じ扱い）
- 水道管は引かない（施設の半径で表現する。操作が増えすぎるため）

### 2.2 ゴミ
- 人口と工業からゴミが出る
- **埋立地**（200 / 15）: 容量あり。満杯になると機能しない。地価を大きく下げる
- **焼却場**（1,200 / 60）: 継続処理。公害を出す
- **リサイクル施設**（1,500 / 70）: 公害なし。処理量は少ない。人口5,000から
- 処理しきれないゴミは、街全体の地価と健康を下げる

### 2.3 送電
- 発電所から**送電線**（20 / 1）で配る。隣接または送電線で繋がることが条件
- 既存の「道路網に繋がれば電気が来る」から変更。より都市経営らしくなる

## 3. 災害

毎月、低い確率で発生。設定で頻度を変えられる（なし／ひかえめ／ふつう／おおい）。

| 災害 | 条件 | 被害 |
|---|---|---|
| 火事 | 消防の手薄な区域 | 範囲内の建物を焼失。消防署が近いと鎮火が早い |
| 地震 | 無条件（低確率） | 広範囲の建物を破壊。道路も寸断 |
| 洪水 | 水辺の低地 | 水辺の建物を破壊 |
| 竜巻 | 無条件（低確率） | 帯状に建物を破壊 |

## 4. 犯罪

- 各タイルに **犯罪率 `crime`**
- 上げる要因: 人口密度、失業、低い地価、低い教育
- 下げる要因: 警察署（半径）、地価、教育
- 影響: 高い犯罪率は地価を下げ、商業の成長を止め、住民が出ていく

## 5. 疫病

- 各タイルに **健康 `health`**（既存）を拡張し、街全体の **感染度 `infection`** を持つ
- 上げる要因: 人口密度、ゴミの滞留、水質汚染、公害
- 下げる要因: 病院（半径）、上下水道、公園
- 影響: 感染が広がると人口が減り、労働力が落ちる
- **診療所**（250 / 18）: 半径8。安価で広く配れる

## 6. 情報と指標（最重要）

### 6.1 データマップ
地図に重ねて見る。切り替えは一覧から。
- 人口密度 / 地価 / 公害 / 犯罪 / 交通量 / 電力 / 水道 / 健康 / 教育 / 消防 / 地区

### 6.2 推移グラフ
過去120か月を記録し、折れ線で見せる。
- 人口 / 資金 / 収支 / 公害 / 犯罪 / 失業率 / 健康

### 6.3 市の統計
一覧で数値を出す。
- 人口・世帯・雇用・失業率・平均地価・平均公害・平均犯罪率
- 収入の内訳（住宅・商業・工業・観光）と支出の内訳（施設種別）
- 電力・水道・ゴミの需給
- 市民の満足度（総合指標）

### 6.4 助言
街の状態から、いま困っていることを日本語で伝える。
例:「でんりょくが たりません」「はんざいが ふえています」「ゴミが あふれています」

### 6.5 条例
街全体に効く方針。複数を同時に有効にできる。
| 条例 | 効果 | 費用 |
|---|---|---|
| 省エネ条例 | 電力需要 -15% | 人口×0.5/月 |
| リサイクル条例 | ゴミ -25% | 人口×0.5/月 |
| 防犯パトロール | 犯罪 -20% | 人口×0.8/月 |
| 無料診療 | 健康 +15、感染 -20% | 人口×1.0/月 |
| 教育振興 | 教育 +15 | 人口×0.8/月 |
| 公共交通補助 | 交通量 -15% | 人口×0.6/月 |

### 足すときに壊れたこと（同じ轍を踏まないために）

新しい制約を後から足すと、既存の釣り合いが崩れて街が全滅した。
いずれも「効き目があること」だけを見て、「効きすぎないこと」を見ていなかった。

| 足したもの | 起きたこと | 直し方 |
|---|---|---|
| 水を必須に | 水道を知らないうちに街が消える | 段階2以上に育つ条件へ変更 |
| 水不足で需要減 | 水ゼロの街で需要-70、何も育たない | 水道を敷いた街だけに限定 |
| 犯罪を質から減点 | 平常時でも成長の敷居に届かない | 45超のときだけ効かせる |
| ゴミが地価を下げる | 敷居を割って街が全滅 | 公害を上げる形に変更、上限も設定 |
| 平均指標 | 空き地込みで平均し、128×128 ではほぼ0 | 建物のある場所だけで平均 |

**教訓**: 新しい罰を足したら、既存の成長の敷居（8/20/34）に対して
どれだけ引くのかを必ず計算する。テストは「効く」だけでなく
「街が消えない」ことも見る。

## 9. 見た目と時間（v3）

### 9.1 タイルの大きさ
**128×64**（従来 64×32 の面積4倍）。窓の桟、ベランダ、店の看板、
瓦の1枚ずつ、雨どい、土台まで描き分けられる。
普段は縮小して表示し、「よせる」縮尺で等倍になって細部が見える。
縮尺は5段（ぜんたい 1/16・ひろい 1/8・ちゅう 1/4・ふつう 1/2・よせる 1/1）。

### 9.2 時間の早送り
0・1・2・4・**10・30倍**。×30 なら1年が約3秒。
1フレームで進める月数に上限（4か月）を設け、早送り中も描画が止まらないようにする。

### 9.3 成長のアニメーション
区分の段階が上がった月は、建物が地面から せり上がる。
`Tile.stageChangedMonth` と `previousStage` で「今月建ったか」を判定し、
月の前半（60%）で建て終える。早送りのときは月が短いので、自然と速く建つ。

### 9.4 条例の費用（v2から修正）
係数を 0.5〜1.0 から **0.05〜0.10** へ下げた。
人口15,000の街で月15,000かかり、収入6,400をはるかに超えていたため、
入れた瞬間に破綻して選択肢にならなかった。
いまは1つあたり税収の1割ほど。

|---|---|---|---|
| だいとし | 約15,000 | +4,300 | 密度最大。条例2つ |

### 9.6 3都市の見分け（v3）

同じ色・同じ高さで並んでいて見分けがつかなかったので、
**建物の色・地形・道路の敷き方・高さの分布**の4点で差をつけた。

| | 色づかい | 地形 | 道路 | 高さ |
|---|---|---|---|---|
| だいとし | 白い石と青いガラス | 湾に面する | 細かい碁盤+大通り十字 | 中心は全て3段階 |
| でんえんとし | 生成りの漆喰とこげ茶の瓦 | 湖と川2本 | ゆったりした区画 | 最高2段階（高層なし） |
| こうぎょうとし | すすけたレンガと灰のトタン | 港に面した平地 | 横長の区画+貨物の大通り | 工業が主 |

色は `City.Style` で切り替える。同じスプライトの色を入れ替えるだけなので、
絵を描き直す必要がない（`IsoBuildings.styled`）。

### 9.7 街並みの様式（v4）

**9種類**を用意し、「じょうほう → せってい」からいつでも切り替えられる。
見た目だけが変わり、シミュレーションには関わらない。

| 様式 | 色づかい |
|---|---|
| ひょうじゅん | 赤い瓦と青いガラス |
| だいとし | 白い石と青いガラスの摩天楼 |
| でんえん | 生成りの漆喰とこげ茶の瓦 |
| こうぎょう | すすけたレンガと灰色のトタン |
| こだい | 日干しレンガと石灰岩。砂漠の都 |
| みらい | 白い合成素材と、光る青 |
| ヨーロッパ | 赤茶の瓦とクリーム色の石 |
| にほんの ちほう | いぶし銀の瓦と白い壁 |
| じぶんで きめる | 遊ぶ人が17か所の色を自分で決める |

`StyleTest` が守っていること:
- どの様式でも**形は変わらない**（塗られた画素の位置が同じ）
- どの様式も、**ほかのどれとも違う色づかい**になっている
- 標準はスプライトをそのまま返す（無駄に作り直さない）

同じ様式を二度求めたときは、作った結果を使い回す。

### 9.8 自分で決める様式（v5）

決められた8種類とは別に、色を自分で決められる様式を用意した（`CustomStyle`）。
「じょうほう → せってい → じぶんで きめる → いろを えらぶ」で開く。

決められる場所は**17か所**。屋根・壁・影を別々に持たせてあるので、
陰影をつぶさずに塗り替えられる。

| 区分 | 場所 |
|---|---|
| じゅうたく | やね／やねの かげ／かべ／かべの かげ |
| ビル | やね／かべ／かげ／ガラス／ひかる ガラス |
| まど | まどの あかり／くらい まど |
| こうじょう | やね／かべ／かげ |
| しせつ | やね／かべ／かげ |

`CustomStyle.Slot` は「置き換えるパレット番号」を `Palette` の定数で直接持つ。
番号を書き写すと、パレットを並べ替えたときに黙ってずれるため。

`CustomStyleTest` が守っていること:
- ふたつの場所が**同じパレット番号を指していない**（片方の変更がもう片方に化ける）
- 何も決めていなければ標準のまま（スプライトをそのまま返す）
- 決めた色が実際に絵に出て、**形は変わらない**
- 色を変えたら、作り置きの絵を使い回さない
- 保存して読み直しても、決めた色が残る

保存は `customStyle` として整数の配列で持つ。
`restore` は短い配列も受けるので、**古いセーブや、あとから場所を足しても壊れない**。

作り直しで分かったこと:
- ゴミ処理が足りず、3都市とも滞留が上限（12,000）に達していた。
  毎月の発生量を測って、焼却場・リサイクルの数を決めた。
- 税率を13%にすると需要への罰が -36 になり、工業がまったく育たなくなった。
  高い税率は収入を増やすが、街を育たなくする。10%前後に留める。
- 工業都市は工業564に対して住民が足りず、工業需要が底を打っていた。
  住宅を厚くして釣り合わせた（工業465・住宅390）。

## 8. 守ること

- **既存の遊びを壊さない**: チュートリアル、お手本の街、セーブは動き続ける
- **1か月の計算は 128×128 で 50ms 以内**（いまは約4ms。余裕はあるが監視する）
- **セーブの後方互換**: 既存のセーブを読めること。足りない値は既定値で埋める
- 各段階でテストを書き、遊べる状態を保ったまま進める
