# PIXELCITY v2 仕様 — 都市経営シミュレーターの全面拡張

既存の v0.4（区分・道路・電力・地価・公害・税収）に、
交通インフラ・環境整備・災害・犯罪・疫病・情報指標を加える。
**隣町との交易は扱わない**。あくまで独立した都市として完結させる。

ベンチマークした作品の考え方（実装は独自。素材・コードの流用はしない）:
- SimCity 2000/4: 区分の発展段階、需要バー、データマップ、条例、災害
- Cities: Skylines: 道路の階層、上下水道、ゴミ、渋滞の可視化、地区ごとの方針
- A列車で行こう / Transport Tycoon: 鉄道と旅客の流れ
- Tropico: 市民個人の状態ではなく、集計値で街の健康を測る考え方

## 1. 交通

### 1.1 道路の階層
| 種類 | 費用 | 維持 | 容量 | 備考 |
|---|---|---|---|---|
| 道路 | 8 | 1 | 100 | 既存 |
| 大通り | 24 | 3 | 300 | 幅が広く、渋滞に強い |
| 高速道路 | 60 | 6 | 800 | 区分は直接つながらない。出入口が要る |
| 鉄道 | 40 | 3 | 600 | 既存。公害を出さない |
| 地下鉄 | 90 | 8 | 900 | 地価を下げない。用地を取らない |

### 1.2 渋滞
各タイルに **交通量 `traffic`** と **容量 `capacity`** を持たせる。
- 発生: 住宅→職場（商業・工業）への移動量を、人口と雇用から求める
- 伝播: 交通網を流れる量を、幅優先で距離減衰させながら配る（経路探索は簡略化）
- 影響: `traffic > capacity` で渋滞。渋滞は地価を下げ、公害を増やし、区分の成長を鈍らせる

### 1.3 公共交通
| 施設 | 費用 | 維持 | 効果 |
|---|---|---|---|
| バス停 | 120 | 8 | 半径6の交通量 -25% |
| 地下鉄駅 | 400 | 25 | 半径8の交通量 -40%。地下鉄に接続が要る |
| 空港 | 3,000 | 120 | 商業需要 +20。公害・騒音あり。人口10,000から |
| 港 | 2,000 | 80 | 工業需要 +20。水辺に隣接 |

## 2. 環境整備（インフラ）

### 2.1 上下水道
- **給水塔**（300 / 20）: 半径10へ給水。人口に対して水量が要る
- **浄水場**（800 / 45）: 半径14へ給水。汚染された水を浄化
- **下水処理場**（900 / 50）: 半径12の水質汚染を除去
- 水が足りないと区分は育たない（電力と同じ扱い）
- 水道管は引かない（施設の半径で表現する。操作が増えすぎるため）

### 2.2 ゴミ
- 人口と工業からゴミが出る
- **埋立地**（200 / 15）: 容量あり。満杯になると機能しない。地価を大きく下げる
- **焼却場**（1,200 / 60）: 継続処理。公害を出す
- **リサイクル施設**（1,500 / 70）: 公害なし。処理量は少ない。人口5,000から
- 処理しきれないゴミは、街全体の地価と健康を下げる

### 2.3 送電
- 発電所から**送電線**（20 / 1）で配る。隣接または送電線で繋がることが条件
- 既存の「道路網に繋がれば電気が来る」から変更。より都市経営らしくなる

## 3. 災害

毎月、低い確率で発生。設定で頻度を変えられる（なし／ひかえめ／ふつう／おおい）。

| 災害 | 条件 | 被害 |
|---|---|---|
| 火事 | 消防の手薄な区域 | 範囲内の建物を焼失。消防署が近いと鎮火が早い |
| 地震 | 無条件（低確率） | 広範囲の建物を破壊。道路も寸断 |
| 洪水 | 水辺の低地 | 水辺の建物を破壊 |
| 竜巻 | 無条件（低確率） | 帯状に建物を破壊 |

## 4. 犯罪

- 各タイルに **犯罪率 `crime`**
- 上げる要因: 人口密度、失業、低い地価、低い教育
- 下げる要因: 警察署（半径）、地価、教育
- 影響: 高い犯罪率は地価を下げ、商業の成長を止め、住民が出ていく

## 5. 疫病

- 各タイルに **健康 `health`**（既存）を拡張し、街全体の **感染度 `infection`** を持つ
- 上げる要因: 人口密度、ゴミの滞留、水質汚染、公害
- 下げる要因: 病院（半径）、上下水道、公園
- 影響: 感染が広がると人口が減り、労働力が落ちる
- **診療所**（250 / 18）: 半径8。安価で広く配れる

## 6. 情報と指標（最重要）

### 6.1 データマップ
地図に重ねて見る。切り替えは一覧から。
- 人口密度 / 地価 / 公害 / 犯罪 / 交通量 / 電力 / 水道 / 健康 / 教育 / 消防 / 地区

### 6.2 推移グラフ
過去120か月を記録し、折れ線で見せる。
- 人口 / 資金 / 収支 / 公害 / 犯罪 / 失業率 / 健康

### 6.3 市の統計
一覧で数値を出す。
- 人口・世帯・雇用・失業率・平均地価・平均公害・平均犯罪率
- 収入の内訳（住宅・商業・工業・観光）と支出の内訳（施設種別）
- 電力・水道・ゴミの需給
- 市民の満足度（総合指標）

### 6.4 助言
街の状態から、いま困っていることを日本語で伝える。
例:「でんりょくが たりません」「はんざいが ふえています」「ゴミが あふれています」

| 防犯パトロール | 犯罪 -20% | 人口×0.8/月 |
| 無料診療 | 健康 +15、感染 -20% | 人口×1.0/月 |
| 教育振興 | 教育 +15 | 人口×0.8/月 |
| 公共交通補助 | 交通量 -15% | 人口×0.6/月 |

### 足すときに壊れたこと（同じ轍を踏まないために）

新しい制約を後から足すと、既存の釣り合いが崩れて街が全滅した。
いずれも「効き目があること」だけを見て、「効きすぎないこと」を見ていなかった。

| 足したもの | 起きたこと | 直し方 |
|---|---|---|
| 水を必須に | 水道を知らないうちに街が消える | 段階2以上に育つ条件へ変更 |
| 水不足で需要減 | 水ゼロの街で需要-70、何も育たない | 水道を敷いた街だけに限定 |
| 犯罪を質から減点 | 平常時でも成長の敷居に届かない | 45超のときだけ効かせる |
| ゴミが地価を下げる | 敷居を割って街が全滅 | 公害を上げる形に変更、上限も設定 |
| 平均指標 | 空き地込みで平均し、128×128 ではほぼ0 | 建物のある場所だけで平均 |

**教訓**: 新しい罰を足したら、既存の成長の敷居（8/20/34）に対して
どれだけ引くのかを必ず計算する。テストは「効く」だけでなく
「街が消えない」ことも見る。

## 9. 見た目と時間（v3）

### 9.1 タイルの大きさ
**128×64**（従来 64×32 の面積4倍）。窓の桟、ベランダ、店の看板、
瓦の1枚ずつ、雨どい、土台まで描き分けられる。
普段は縮小して表示し、「よせる」縮尺で等倍になって細部が見える。
縮尺は5段（ぜんたい 1/16・ひろい 1/8・ちゅう 1/4・ふつう 1/2・よせる 1/1）。

### 9.2 時間の早送り
0・1・2・4・**10・30倍**。×30 なら1年が約3秒。
1フレームで進める月数に上限（4か月）を設け、早送り中も描画が止まらないようにする。

### 9.3 成長のアニメーション
区分の段階が上がった月は、建物が地面から せり上がる。
`Tile.stageChangedMonth` と `previousStage` で「今月建ったか」を判定し、
月の前半（60%）で建て終える。早送りのときは月が短いので、自然と速く建つ。

### 9.4 条例の費用（v2から修正）
係数を 0.5〜1.0 から **0.05〜0.10** へ下げた。
人口15,000の街で月15,000かかり、収入6,400をはるかに超えていたため、
入れた瞬間に破綻して選択肢にならなかった。
いまは1つあたり税収の1割ほど。

| 見本 | 人口 | 収支 | 特徴 |
|---|---|---|---|
| だいとし | 約15,000 | +4,300 | 密度最大。条例2つ |
| でんえんとし | 約13,800 | +5,200 | 公害3。火力0、リサイクルのみ |
| こうぎょうとし | 約11,300 | 均衡 | 工業>住宅。資金64万で最厚 |

### 9.6 3都市の見分け（v3）

同じ色・同じ高さで並んでいて見分けがつかなかったので、
**建物の色・地形・道路の敷き方・高さの分布**の4点で差をつけた。

| | 色づかい | 地形 | 道路 | 高さ |
|---|---|---|---|---|
| だいとし | 白い石と青いガラス | 湾に面する | 細かい碁盤+大通り十字 | 中心は全て3段階 |
| でんえんとし | 生成りの漆喰とこげ茶の瓦 | 湖と川2本 | ゆったりした区画 | 最高2段階（高層なし） |
| こうぎょうとし | すすけたレンガと灰のトタン | 港に面した平地 | 横長の区画+貨物の大通り | 工業が主 |

色は `City.Style` で切り替える。同じスプライトの色を入れ替えるだけなので、
絵を描き直す必要がない（`IsoBuildings.styled`）。

### 9.7 街並みの様式（v4）

**9種類**を用意し、「じょうほう → せってい」からいつでも切り替えられる。
見た目だけが変わり、シミュレーションには関わらない。

| 様式 | 色づかい |
|---|---|
| ひょうじゅん | 赤い瓦と青いガラス |
| だいとし | 白い石と青いガラスの摩天楼 |
| でんえん | 生成りの漆喰とこげ茶の瓦 |
| こうぎょう | すすけたレンガと灰色のトタン |
| こだい | 日干しレンガと石灰岩。砂漠の都 |
| みらい | 白い合成素材と、光る青 |
| ヨーロッパ | 赤茶の瓦とクリーム色の石 |
| にほんの ちほう | いぶし銀の瓦と白い壁 |
| じぶんで きめる | 遊ぶ人が17か所の色を自分で決める |

`StyleTest` が守っていること:
- どの様式でも**形は変わらない**（塗られた画素の位置が同じ）

- 標準はスプライトをそのまま返す（無駄に作り直さない）

同じ様式を二度求めたときは、作った結果を使い回す。

### 9.8 モニュメントを原寸で描く（v5）

以前のモニュメントは、64ドットで形を決めてから4倍に引き伸ばしていた。
そのため最小の粒が 4×4 の塊になり、柱・窓・時計の針といった細部が
**そもそも描けなかった**。いまは最終の大きさ（256ドット）のまま描いている。

細部を出すために、次の部品を用意した（`MonumentSprites`）。

| 部品 | 使いどころ |
|---|---|
| `isoBox` | 左右の壁と菱形の上面を持つ、等角の箱 |
| `column` / `colonnade` | 円柱と、その列。コロッセオ・ピサの斜塔 |
| `dome` | ドーム。`onion` を上げるとたまねぎ形（タージ・マハル） |
| `archway` | 縁と見込みのあるアーチ。ただ穴を開けるのではない |
| `entablature` | 軒。水平の帯で建築らしい区切りを作る |
| `lattice` | 鉄骨の筋交い。東京タワー |
| `Ramp` | 素材ごとの5〜6段の階調。曲面の陰影に使う |

素材の色は `Palette` に34色を足した（大理石6段・緑青5段・石灰岩5段・
ピラミッドの石5段・鉄骨4色・ロンドンの砂岩4段・金3段・影2色）。
既存の石や砂の4段では、ドームや像の曲面で段差が目立つため。

`SpritesTest` が守っていること:
- **引き伸ばしに戻っていない**（4の倍数でない位置にも色の変わり目がある）
- のっぺりしていない（どのモニュメントも8色以上）
- どれも**ほかと見分けがつく**
- 足元が上より広い（クォータービューで宙に浮かない）

`MonumentPreviewTest` は試験ではなく道具。
`-Ppixelcity.preview=<書き出し先>` を付けて走らせると、
各モニュメントと一覧を PNG で書き出す。目で確かめるために使う。
（`java.awt` は Android の classpath にないので、PNG は自前で組み立てている。）

作り直しで分かったこと:
- **正面を四角く塗って上に菱形を乗せても、切妻屋根にしか見えない。**
  屋根が菱形に見えるのは、左右の壁と上面を3面で組んだときだけ（`isoBox`）。
- 足元の菱形（`platform`・`groundShadow`）を絵より先に描くと、
  **まだ何も描かれていない「内側の空」まで塗りつぶす**。
  コロッセオの輪の中が板に見えたのはこれが原因だった。
- 円や楕円を**角度で回して描くと、端で縦の隙間が開く**。
  x を1ドットずつ回して、その x での角度を逆算するとそろう。
- 低い視点では、**高い壁の向こうは見えない**。
  コロッセオの観客席が見えないのは正しい。見えるのは崩れた側からだけ。

### 9.9 つまんで拡大・縮小（v5）

2本指の間隔が **1.5倍** になったら1段寄り、**1/1.5** になったら1段引く。
拡大率は5段（1/16〜1/1）の飛び飛びなので、連続に伸縮させず段で動かす。

段を変えるときは、**2本指の中点が指しているタイルを動かさない**。
画面の中心を軸にすると、広げた場所がどこかへ行ってしまう。
`zoomAround` が、変える前後で同じ点のタイル座標を測り、その差だけ地図を送る。

つまんだあとは `handleTap` を呼ばない。呼ぶと、指を離した場所に
道路が敷かれてしまう。

`PinchZoomTest`（実機）が守っていること:
- 広げると寄り、縮めると引く
- 1割ほどの動きでは変わらない（手ぶれで拡大率が動かない）
- 両端で止まる

`adb shell input` では2本目の指を送れないので、
[MotionEvent] を組み立てて `onTouchEvent` に直接流している。

### 9.10 音（v5）

絵と同じく、**音も式から作る**（`audio/`）。録音物・第三者の音源は使っていない。

| | 中身 |
|---|---|
| `Waves` | 矩形波・三角波・正弦波・雑音。22.05kHz モノラル16bit |
| `Sfx` | 効果音14種 |
| `Bgm` | 曲3つ（あさ・まち・くるしいとき） |
| `Audio` | 鳴らす係。`AudioTrack` を直接使う |

**効果音**は、道路・区分・施設・破壊・却下・画面の開閉・モニュメント完成・
人口の節目・災害・破産など。よく鳴るものほど短くしてある（0.06〜0.28秒）。
区分の3つは同じ形で高さだけ変えてあり（E4/A4/C4）、
見ていなくても住宅・商業・工業を聞き分けられる。

**曲**は街の様子で変わる。人口2,000未満は「あさ」、
それ以上は「まち」、資金が尽きかけ・借金中は「くるしいとき」。

音は「じょうほう → せってい」の一番上で、効果音と音楽を別々に切れる。
設定は `Settings`（[SaveGame] とは別）に持つ。
音を切ったかは街ごとの話ではなく遊ぶ人の好みなので、
どのスロットを開いても同じであってほしい。

`AudioTest` が守っていること:
- どの音も無音でない／割れていない
- 終わりが静か（プチッと切れない）
- 曲の頭と尻が静か（繰り返しの継ぎ目で飛ばない）
- よく鳴る音は 0.35秒以下
- 何度作っても同じ音（雑音の種を固定してある）

`AudioPreviewTest` は道具。`-Ppixelcity.preview=<先>` で WAV を書き出す。

作り分けで分かったこと:
- 個々の振幅を「重ねても割れない」ように決めると、**全体が小さすぎて聞こえない**。
  最後にまとめて持ち上げ、`toPcm` が振り切れる前にならす形にした。
- 曲を繰り返すと、継ぎ目で**プチッと鳴る**。
  頭と尻に 0.012秒の出入りをつけて消した。
- 効果音は `SoundPool` ではなく短い `AudioTrack` を使い捨てる。
  SoundPool は音の入ったファイルを読む前提で、配列を直接渡せない。
- 曲は `setLoopPoints` で端末側に繰り返させる。
  自前で書き足すと、画面が重いときに音が途切れる。

### 9.11 えらんでから じっこう（v6）

マスをタップしても、その場では何も起きない。青い影がつくだけ。
「じっこう」を押して初めて建つ（壊れる）。

押し間違いで街が壊れたり、資金が減ったりしないようにするため。
以前は指が触れた瞬間に実行されていたので、
地図を送るつもりで触れただけでも道路が敷かれてしまった。

- タップで1マス、なぞって複数マスをまとめて選べる
- 選んであるマスをもう一度押すと外れる。
  なぞり始めが選択済みなら、なぞるあいだは「外す」側になる
- 帯に「たてる Nマス $金額」を出す。押す前に、何にいくらかかるか見える
- 資金が足りなければ、建てられるところまでで止めて、その数を伝える
- 道具を変えたら選択は捨てる（道路のつもりのマスに発電所が建っては困る）
- 置けない場所はそもそも選ばせない。
  選べてしまうと「じっこう」しても何も起きず、理由も分からない

帯はツールバーの上に重ねる。地図の大きさは変えない。
選ぶたびに地図が動くと、狙いが定まらないため。
チュートリアル中は、説明の帯よりさらに上に置く（重ねると釦が押せない）。

`SelectionTest`（実機）が守っていること:
- タップしただけでは何も建たない
- 複数マスを選べる／もう一度押すと外れる／なぞってまとめて選べる
- 道具を変えると選択が消える
- 「じっこう」で、選んだマスが**全部**建ち、選択が空になる

### 9.12 全画面（v6）

余白をなくし、画面いっぱいに描く。

**左右の余白**は、論理解像度を固定していたのが原因だった。
480ドットを1080pxの端末に整数倍（2倍）で描くと960pxで、120px余る。
そこで**論理解像度を「端末の幅 ÷ 倍率」で決める**ようにした。
1080px なら 540ドット×2倍でちょうど埋まる。
倍率は整数のままなので、1ドットは正方形で、ぼやけない。

| 端末 | 倍率 | 論理の幅 | 余白 |
|---|---|---|---|
| 1080 | 2 | 540 | 0 |
| 1440 | 3 | 480 | 0 |
| 720 | 1 | 720 | 0 |

`GameView.LOGICAL_W` は定数から変数になった。
計算は `layoutFor` に一か所だけ置く。
タイトル・スロット・おてほんの各画面も同じ計算を使う。
ばらばらに書くと、画面を移ったときに大きさが変わる。

**上下の余白**は2つ原因があった。
- 状態表示と操作の帯 → `WindowInsetsControllerCompat` で隠す。
  画面の端から引き出せば出てくる
- `LOGICAL_H_MAX` が 1000 で、1080×2400 の端末に必要な 1200 に足りない
  → 1600 に引き上げ

作り直しで分かったこと:
- 半端な倍率（2.25倍など）で引き伸ばすと、1ドットの大きさが揃わずぼやける。
  ドット絵では、倍率は整数に保ったまま論理解像度のほうを変える。
- 画面を切り替えて組み立てる作りだと、`onResume` のとき view がまだ無い。
  音を鳴らし直すのは `onAttachedToWindow` でも行う。

### 9.13 指に吸い付く動き（v7）

**つまむ操作を連続にした。** 以前は拡大率を5段で持ち、指が一定以上
ひらいた瞬間に1段跳んでいた。いまは指の開きの比を、そのまま倍率の比にする。

描画は整数の掛け算で行うので、倍率は分母を 64 に固定した分数で表す。
1/16 から 1/1 までを 1% 未満の誤差で表せる。

**地図送りのかくつきを直した。** 原点の計算が

```
Iso.screenX2(camX, camY).toInt() * zoomNum / zoomDen
```

と、**先に整数へ落としてから割って**いた。
1/4 のときは 1ドットの差が 4ドットに化け、指を動かしても
動いたり動かなかったりしていた。小数のまま割り、最後に一度だけ丸める。

| ズーム | 直す前の1歩 | 直したあと |
|---|---|---|
| 1/16 | 0〜4ドット | 0〜1ドット |
| 1/4 | 0〜2ドット | 0〜1ドット |

同じ式を `mapCoords` でも使う。描く側とずれると、
押した場所と選ばれるマスが食い違う。

### 9.15 通知の欄・操作の欄（v7）

**欄は隠さない。** 一度は隠したが、遊んでいる最中にうっかり
引き出してしまったり、戻る操作ができずに困る。

かわりに「絵は画面の端まで描き、文字と釦は欄の内側に置く」形にした。
余白は消えるが、時計や戻る釦には重ならない。

欄の高さは `SystemBars` が持つ。画面ごとに読み取ると、
まだ高さが届いていないうちに描き始めてしまい、画面によって位置がずれる。
`MainActivity` が一度だけ受け取り、どの画面もそこから引く。

### 9.16 欄と重ねない（v8）

「画面いっぱいに描く」を、**欄を隠す**やり方でやったのは誤りだった。
遊んでいる最中にうっかり引き出してしまったり、戻る操作ができずに困る。

いまは **欄は出したまま、絵だけを端まで伸ばし、文字と釦は欄の内側に置く**。
余白は消えるが、時計や戻る釦には重ならない。

欄の高さは `SystemBars` が持ち、`MainActivity` が一度だけ受け取る。
画面ごとに読み取ると、まだ高さが届いていないうちに描き始めてしまい、
画面によって位置がずれる。

じょうほう画面・いろを えらぶ画面は、自分では倍率を知らないので、
`GameView` が描くときに欄の高さを渡す。

### 9.19 自分で決める様式（v5）

決められた8種類とは別に、色を自分で決められる様式を用意した（`CustomStyle`）。
「じょうほう → せってい → じぶんで きめる → いろを えらぶ」で開く。

決められる場所は**17か所**。屋根・壁・影を別々に持たせてあるので、
陰影をつぶさずに塗り替えられる。

| 区分 | 場所 |
|---|---|
| じゅうたく | やね／やねの かげ／かべ／かべの かげ |
| ビル | やね／かべ／かげ／ガラス／ひかる ガラス |
| まど | まどの あかり／くらい まど |
| こうじょう | やね／かべ／かげ |
| しせつ | やね／かべ／かげ |

`CustomStyle.Slot` は「置き換えるパレット番号」を `Palette` の定数で直接持つ。
番号を書き写すと、パレットを並べ替えたときに黙ってずれるため。

`CustomStyleTest` が守っていること:
- ふたつの場所が**同じパレット番号を指していない**（片方の変更がもう片方に化ける）
- 何も決めていなければ標準のまま（スプライトをそのまま返す）
- 決めた色が実際に絵に出て、**形は変わらない**
- 色を変えたら、作り置きの絵を使い回さない
- 保存して読み直しても、決めた色が残る

保存は `customStyle` として整数の配列で持つ。
`restore` は短い配列も受けるので、**古いセーブや、あとから場所を足しても壊れない**。

作り直しで分かったこと:
- ゴミ処理が足りず、3都市とも滞留が上限（12,000）に達していた。
  毎月の発生量を測って、焼却場・リサイクルの数を決めた。
- 税率を13%にすると需要への罰が -36 になり、工業がまったく育たなくなった。
  高い税率は収入を増やすが、街を育たなくする。10%前後に留める。
- 工業都市は工業564に対して住民が足りず、工業需要が底を打っていた。
  住宅を厚くして釣り合わせた（工業465・住宅390）。

## 8. 守ること

- **既存の遊びを壊さない**: チュートリアル、お手本の街、セーブは動き続ける
- **1か月の計算は 128×128 で 50ms 以内**（いまは約4ms。余裕はあるが監視する）
- **セーブの後方互換**: 既存のセーブを読めること。足りない値は既定値で埋める
- 各段階でテストを書き、遊べる状態を保ったまま進める
